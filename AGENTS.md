# Commit messages

Always use Conventional Commits for commit messages:

```text
<type>[optional scope][!]: <description>
```

Choose a type that describes the change, such as `feat`, `fix`, `docs`,
`refactor`, `perf`, `test`, `build`, `ci`, or `chore`. Mark breaking changes
with `!` or a `BREAKING CHANGE:` footer.

Examples:

- `feat(jira): support attachment downloads`
- `fix: preserve pagination cursors on short pages`
- `docs: clarify API token setup`
